# Buryad UX/Mobile V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert Buryad into a mobile-first learning app with explicit exercise progression, durable multi-user progress, progressive-disclosure reference tools, improved accessibility and automated responsive smoke tests.

**Architecture:** Keep FastAPI/PostgreSQL and static ES modules. Add small pure JS modules for scheduling/progress merging, split large UI behavior into focused modules, and keep server APIs backwards compatible while adding bulk progress merge. Responsive UI remains CSS-driven with desktop top navigation and mobile bottom navigation.

**Tech Stack:** FastAPI, SQLAlchemy, PostgreSQL, vanilla ES modules, CSS, Node tests, Playwright, Docker, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-17-ux-mobile-v2-design.md`

## Global Constraints
- Preserve existing content, auth and public domain `https://buryad.buuzoed.dev`.
- Mobile layouts must work from 320px width without horizontal scrolling.
- No auto-advance after a correct answer.
- Guest progress must merge on login/register.
- Use verified transcripts only for automatic listening scores.
- Production remains exposed only through nginx; app port stays loopback-only.
